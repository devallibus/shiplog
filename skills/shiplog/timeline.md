# Capture discussion and handoffs

Use [references/records.md](references/records.md) for the record format and capture rules.

At a useful checkpoint, save uncaptured human discussion and any assistant replies needed to understand it. Keep each original message intact. Add new decisions, discoveries, or evidence once, then update the current summary with source links. Do not duplicate the same reasoning in a commit body, issue comment, and PR body.

Before a handoff, capture available discussion and leave the goal, limits, completed work, checks, blockers, and next action. If the runtime warns of context reduction, capture before it happens. If earlier text is already unavailable, record the gap rather than reconstructing it.

A routine start, resume, or unchanged status needs no comment. New human discussion still needs capture even when the implementation plan stays the same.
